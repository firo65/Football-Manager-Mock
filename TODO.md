   - On campaign completion *or* Week 6 / Week 11 elimination, allow the Captain to pass down one permanent **Legacy Spark** (`+3 Starting Attack/Tech/Defense` or `+5% Stamina Conservation`) to the next 12-week run.

4. **Floating Stat Gain Popups & Grade-Up Fanfare (`C ➔ B!`)**

5. **1-Line Visual Progress Tooltip on Grades & Locked Traits**

## Part B: Live2D & 2.5D Animated Menu Avatars

Right now only plain flat character images are available, without separated `.psd` layers or exported `.moc3` Live2D models. Below is what this AI model can build directly from plain images today, what requires external Live2D tooling, and the 3-phase integration roadmap for [`src/components/CharacterStage.tsx`](src/components/CharacterStage.tsx).

### What This AI Model Can Rig & Animate Directly (From Plain Images)
1. **2.5D Procedural WebGL / Canvas / CSS Mesh Rig ("Pseudo-Live2D")**
   - Use local Python scripts (`rembg` / `Pillow` / `OpenCV`) to strip backgrounds cleanly, standardize canvas proportions, and separate basic silhouette masks/planes.
   - Drive **continuous idle breathing** (subtle torso/shoulder vertical sine & chest scale), **cursor/touch parallax tilt**, **procedural hair/jersey sway shaders**, **tap/victory squash-and-stretch bounce**, and **mood particle FX** (fire/sparkles on `Peak`/`fired_up`, dim sweat vignette on `Tired`) directly in React/Canvas inside `CharacterStage.tsx`.
2. **Sprite-Overlay Eye Blinking & Dialogue Lip-Sync**
   - Crop or generate closed-eye blink frames and mouth open/closed overlay patches aligned to each portrait, triggering natural timed eye blinks and subtle mouth motion synced with the existing character dialogue typewriter in `CharacterStage.tsx`.
3. **Full Live2D Cubism SDK Wiring (`pixi-live2d-display` / WebGL)**
   - Implement the complete React `<Live2DStage />` canvas component, expression mapping (`neutral`, `happy`, `fired_up`, `tired`, `serious`), tap hit-boxes, and responsive scaling so exported `.model3.json` models drop straight in.

### What Cannot Be Generated by Code Alone
- Proprietary binary **`.moc3` skeletal rigs** must still be authored/exported using **Live2D Cubism Editor** (free tier works for small models) or an open-source 2D bone tool like **Inochi2D** once artwork is split into PSD layers.

### 3-Phase Avatar Integration Plan (`src/components/CharacterStage.tsx`)
- **Phase 1 — Plain PNG Drop-In + Procedural 2.5D Stage (Immediate, No PSD Required)**
  1. Add plain transparent PNG portraits into `public/avatars/<avatarKey>.png` (matching `player.avatarKey` in `mockData.ts`, falling back seamlessly to the current vector bust when missing).
  2. Run a local background-cleanup/cropping script if starting from non-transparent images.
  3. Upgrade `CharacterStage.tsx` with idle breathing keyframes, pointer parallax lean, reactive tap hop, and floating expression FX particles (`🔥`, `✨`, `💧`) keyed off `dialogueContext` mood/expression.
- **Phase 2 — Multi-Plane Depth & Blink/Mouth Overlay (Optional Pre-Cubism Polish)**
  1. Split key hero portraits into 3–4 PNG layers (`back_hair`, `body`, `head`, `front_hair`) + `blink`/`mouth` small overlay patches.
  2. Render via a lightweight layered Canvas/Pixi stage for authentic head-turn parallax, hair sway, timed blinking, and speech sync.
- **Phase 3 — Native Live2D `.moc3` Swap**
  1. Install `pixi.js` + `pixi-live2d-display` (and Live2D Cubism Core runtime).
  2. Drop exported `public/live2d/<avatarKey>/<model>.model3.json` rigs into the project; `CharacterStage.tsx` automatically upgrades matching characters to full Live2D while keeping Phase 1/2 avatars working seamlessly alongside them.
